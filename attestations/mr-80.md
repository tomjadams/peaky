## security-reviewer findings

### WARN: CODEOWNERS enforcement depends on protected branch settings

**File:** `.gitlab/CODEOWNERS:1`
**Evidence:** GitLab only enforces codeowner approval when the protected branch setting "Require approval from code owners" is enabled. That setting is not in version control and is not present in this diff. If it is disabled, or if "Prevent bypassing CODEOWNERS approval" is not set, any project member (including Maintainers/Owners) can still merge changes without resilience-taskforce review.
**Fix:** Enable "Require approval from code owners" on the protected default branch. Also enable "Prevent bypassing CODEOWNERS approval" to prevent high-privilege accounts from overriding the rule.

### WARN: Approval authority is delegated to an external LDAP group

**File:** `.gitlab/CODEOWNERS:2`
**Evidence:** The rule points to `@adyen/ldap-groups/resilience-taskforce`, whose membership is managed outside this repository (in LDAP/GitLab group linkage). A membership change in that LDAP group — accidental or malicious — immediately changes who can approve every merge without a code review.
**Fix:** Document a membership review cadence for `adyen/ldap-groups/resilience-taskforce` and add monitoring/alerting for membership changes. Prefer a small, dedicated approval group if the LDAP group is large or broadly shared.

**File:** `.gitlab/CODEOWNERS:2`
**Evidence:** The `*` glob applies to all files, including `.gitlab/CODEOWNERS`. Any future modification of the file itself would require resilience-taskforce approval, providing a layer of self-protection against an attacker who can push to an open branch. This defense is only effective when the branch protection settings described in the WARN above are also enabled.
