## Local-first architecture

This section stays intentionally brief. It records the durable direction, while the [local-first walkthroughs](./walkthroughs/local-first/) carry the detailed runtime, data-model, API, security, and auditing guidance.

| Stage | Direction | Notes |
| ----- | --------- | ----- |
| Stage 1 | Client-local foundation | Drizzle-backed schema, SQLite WASM + OPFS, reactive query layer, local outbox, entitlement snapshots, event-backed history, sync simulator |
| Stage 2 | Production remote sync | Remote Postgres + PowerSync; replaces intentional read bridges |
| Stage 3 | Integration and hardening | Stable `/integrations/*` machine APIs, selective replication tuning, production operational concerns |
| Stage 4 | Collaboration escalation if needed | CRDTs only if structured optimistic collaboration proves insufficient |

Key standing decisions:

- **The local database is the source of truth for editable sessions**
- **Human-oriented shared APIs remain primary; `/integrations/*` is machine-led and case-by-case**
- **Auditability is append-only and CloudTrail-inspired**
- **Template collaboration stays structured first** — before any CRDT escalation
- **The sync simulator is for protocol rehearsal, not durability validation**
- **The browser is untrusted** — server re-validates entitlements on every sync push

## Conventions Established

### Component Patterns

- **BEM class naming**: All components use `component__element--modifier` pattern
- **Composables for shared state**: Cross-component state uses `use*` composables with `useState` for SSR
- **Cell type registry**: DataTable uses component registry pattern for cell rendering
- **Services are plain TypeScript, composables are Vue glue**: Domain logic in `app/services/`, no Vue imports permitted

### API Patterns

- **Review-centric routes**: Primary pattern is `/api/reviews/:id/*`
- **Bulk operations**: `/api/{resource}/bulk/{action}` pattern
- **Sync push is the real API surface**: All local mutations flow through `server/api/sync/push.post.ts`
- **Zod validation on all POST endpoints**: Runtime schema validation, not just TypeScript types

### Testing Patterns

- **Three-tier strategy**: Unit (services, composables) → Integration (API contracts) → E2E (user journeys)
- **Unit test principles**: No I/O, test production code, deterministic time/randomness, right suite for right test
- **Coverage ratchet**: Thresholds prevent regression — raise as coverage improves, never lower
- **Repository lints live in `tests/guards/`, not `tests/unit/`**: assertions about files (generated output matches its source, a spec still describes the code it claims to) are not unit tests. They run in `make test` because they cost milliseconds, but filing them as unit tests hides that they do I/O and test no behaviour
- **E2E seeding**: Via `window.__peakySeed` mutation functions (dev-only), never raw SQL
- **Quality gate**: `make mr` runs all checks before MR submission

### Security Patterns

- **nuxt-security module**: CSP, HSTS, rate limiting, XSS validation — see [Security walkthrough](./walkthroughs/local-first/security)
- **DevTools globals dev-only**: `window.peakyDB` and `window.__peakySeed` guarded by `import.meta.dev`
- **Outcome-based security reviews**: Security-reviewer droid asks "what can an attacker do?" not "does the code match a pattern?"

### Formal Verification Patterns

- **OpenSpec design and FizzBee model are co-equal renderings of one contract**: the prose (WHEN/THEN scenarios) and the proof (invariants) describe the same truth. They cannot disagree. A divergence is a defect in either the model or the design, never a conflict to arbitrate.
- **1:1 scenario to invariant**: every OpenSpec scenario owes a FizzBee invariant and every invariant owes a scenario. A missing counterpart on either side is the signal that one artifact is incomplete. Reconciliation happens at authoring time, by writing the pair together, not via a separate traceability document.
- **A model derived from an implementation inherits its bugs**: the AIMD spec copied `Math.floor(n * 1.5)` from `ConcurrencyController`, so it reproduced the growth stall at `n = 1` (a controller collapsed to `min` never recovering) instead of exposing it — both assertions held throughout. Properties must be stated from the requirement ("success must make progress while there is headroom"), not transcribed from the code.
- **A passing spec proves the model self-consistent, nothing more**: the checker explores the `.fizz` model and never reads the implementation. Claiming a green `make verify` makes a code change "safe" is false. Conformance needs the code in the loop, which is what `make verify-mbt` does.
- **Whether code warrants a spec is a human judgement, and stays one**: the test is "must this hold over every interleaving, retry, or crash point?" — concurrent actors, terminating retry loops, idempotent replay, cursor ordering. Anything a table-driven test can pin gets a table-driven test. Automating that decision produces a check everyone mutes; what is automated is either side of it — the drift guard for code already named in a `# MODELS` block, and a four-entry risk zone (`app/services/sync/**`, `app/local-db/migrations.ts`, `shared/db/schema/sync.ts`, `services/internal/syncengine/**`) that prompts the reviewer to ask the question out loud.
- **Spec↔code links are two-way and machine-checked**: a spec names its subjects in `# MODELS`; each subject carries a `Formal model: ...` comment. The comment proves nothing about behaviour — it exists so the obligation is visible while editing the code, which is when it matters. Constant equality and MBT are the checks that actually bind.
- **No standalone traceability file**: `formal_verification/sync/sse_gap_register.md` was deliberate brownfield scaffolding for an existing, undocumented SSE contract, not the template for new work. Mapping invariants to *gaps* (what is broken today) instead of *design scenarios* (what must always hold) is what made invariant I4 look orphaned; the durable relationship is invariant to scenario, and gaps are only the subset of properties currently violated.
