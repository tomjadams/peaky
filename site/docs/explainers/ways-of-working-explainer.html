The dev loop — idea to shipped to learned-fromthe product loop above feeds this loop

Fast and repeatable — an issue is picked up from the backlog and moves through seven stages. Each one runs an command or a deterministic gate; step through it.

What is a droid, actually?.factory/droids/*.md

Four things to demystify before the roster: it's a markdown file, it's read-only, findings are graded, and it follows the same pattern as commands and skills.

Adversarial + outcome droid roster — 15 AI reviewers.factory/droids/ · 14 adversarial + 1 rtf-outcome-verifier

The name is the scope — each droid reviews one angle only. New domains just add a new droid. rtf-outcome-verifier sits adjacent to the adversarial roster — it runs by default against the change's acceptance criteria (auto-discovered from the branch issue or openspec change) and asks "did the diff actually deliver them?", which the 14 adversarial droids cannot. orchestrates the lot: path-routed by default, rtf-security-reviewer always, evidence-paired on every BLOCK/WARN finding, exit codes 0/1/2/3 — the loudest signal wins.

Enrich project specific patterns.factory/review-context/

The seven pillars are the lens, but each droid loads project-specific context before reviewing. That's what makes a Go reviewer check HLC ordering, not just "concurrency."

What every reviewer looks forseven pillars, inspired by CodeRabbit

Every adversarial droid applies the same lens to its own domain. A Go reviewer checks concurrency; a security reviewer checks trust boundaries \u2014 but both reason through the same pillars. The outcome droid adds the eighth question: did this change actually satisfy its acceptance criteria?

The deterministic floor — local gatescatch issues before they leave your machine

Cheap, deterministic feedback first, locally. CI continues the suite — the point: agents only ever run on already-clean code.

The quality floor — static analysis + testslinters prevent · tests prove

Two systems, one floor: linters prevent whole classes of bugs statically — one per language, same concerns — while the pyramid proves behaviour. When a reviewer droid keeps catching something, it graduates into a linter rule and the droid shrinks.
